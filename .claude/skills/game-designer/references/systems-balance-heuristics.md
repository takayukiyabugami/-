# Systems And Balance Heuristics

Use these checks to make gameplay design concrete and testable.

## Core Loop

- The loop should include action, feedback, reward or consequence, and a reason to repeat.
- The player should understand what improved after each loop: skill, resources, knowledge, position, or future options.
- If the loop requires waiting, walking without decisions, or repeated cleanup, compress it.
- One strong repeated decision is better than five weak chores.

## Rules

- Define what the player can do, what the system can do back, and what changes state.
- Each rule should either create a decision, teach a pattern, express the fantasy, or constrain balance.
- Hidden rules need visible symptoms. Unreadable rules feel unfair even when mathematically balanced.
- Prefer exceptions that create drama. Remove exceptions that only add memory burden.

## Combat And Challenge

- Every threat needs a readable tell, a consequence, and at least one counterplay option.
- Good enemy sets create role contrast: pressure, area denial, pursuit, protection, disruption, burst, support.
- Challenge should test the current lesson before combining it with older lessons.
- Damage is not the only pressure. Use time, position, information, resource drain, opportunity cost, and attention split.
- Avoid pure stat checks unless the game is explicitly about preparation and build planning.

## Level Design

- Teach safely, test under pressure, then remix.
- Use spatial rhythm: safe space, choice point, pressure space, reward space.
- Place landmarks or UI anchors so players know where they are and what changed.
- Make the critical path readable before adding optional paths.
- If failure sends the player far back, the repeated segment must still contain decisions.

## Progression

- Early unlocks should deepen existing verbs before adding entirely new systems.
- Growth should change player choices, not only increase numbers.
- Rewards need cadence: small frequent confirmation, medium tactical change, rare identity-changing reward.
- Meta-progression can soften failure, but should not make the first run feel pointless.
- If a build has no tradeoff, it is probably just an upgrade tax.

## Difficulty

- Difficulty should rise by adding complexity, speed, pressure, or stricter resource demands, not by hiding basic information.
- Separate onboarding difficulty from mastery difficulty.
- Give players recovery windows after high pressure.
- A fair failure answers: what happened, why it happened, what to try next.
- Rubber-banding should be subtle. Obvious correction damages agency.

## Balance

- Identify the dominant strategy and decide whether to embrace, weaken, price, or counter it.
- Track balance in ranges: too weak, acceptable, too strong.
- Tune one axis at a time when possible.
- Use cost, cooldown, risk, commitment, scarcity, counterplay, and opportunity cost before raw nerfs.
- If a system has no tuning knob, add one before adding more content.

## UX And Feel

- Controls should match fantasy and reaction time. Precision games need low latency and clear input buffering.
- Feedback should confirm intent immediately, then show outcome.
- Important state should be visible at the moment of decision.
- Reduce mental load at high action intensity. Move details to quieter moments.
- "Heavy" feel can come from latency, long recovery, unclear acceleration, weak hit feedback, slow camera, or delayed reward.

## Player Psychology

- Agency: the player believes choices caused the result.
- Mastery: the player sees a skill gap and a path to close it.
- Tension: the player risks something meaningful but recoverable.
- Curiosity: the next room, card, enemy, unlock, or rule interaction promises new information.
- Fairness: the player can explain failure without blaming the interface.
- Relief: after pressure, give confirmation, space, or reward.
